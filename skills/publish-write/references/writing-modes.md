# 집필 모드 가이드

`/publish-write` 스킬이 지원하는 4가지 프로젝트 유형별 상세 집필 절차와 유의사항.

---

## 공통 사전 원칙

모든 집필 모드에서 다음 원칙이 적용된다.

### 저자 프로필 로드

집필 시작 전 반드시 4개 파일 전체를 로드한다:

```
authors/{author_id}/style.yaml          → 어투·문장 구조·수사법
authors/{author_id}/theology.yaml       → 신학적 입장 (구원론, 종말론 등)
authors/{author_id}/sermon_pattern.yaml → 설교 구조 패턴
authors/{author_id}/vocabulary.md       → 자주 쓰는/피하는 표현
```

프로필은 모든 초안의 기준이다. "좋은 글"이 아니라 "이 저자가 쓸 법한 글"을 목표로 한다.

### wiki/ 검색 전략

`shared/references/search-strategy.md`를 따른다. 요약:

```
Level 0: 카테고리 _index.md → 관련 기사 후보 선정 (토큰 최소)
Level 1: 후보 기사 index.md summary → 관련성 확인 (토큰 소)
Level 2: chunks/ 상세 내용 → 실제 집필 참조 (필요한 것만)
```

토큰 효율을 위해 Level 0에서 충분히 좁힌 후 Level 2로 진입한다.

### 토큰 관리

긴 원고를 작업할 때 컨텍스트 한도를 넘지 않도록 **챕터 단위 작업**을 원칙으로 한다:

- 현재 챕터 작업 시: 이전 챕터 전체 내용은 컨텍스트에서 제거
- 이전 챕터 요약(3-5문장)만 유지하여 흐름 연결
- wiki/ 검색은 챕터별로 새로 실행 (관련 자료가 다를 수 있음)
- 저자 프로필 4개 파일은 매 챕터 시작 시 재확인

## 1. new_book — 신규 도서

### 개요

저자의 KB를 바탕으로 새로운 책의 초안을 처음부터 작성한다. 목차가 없는 경우 KB를 분석하여 자동 제안할 수 있다.

### 집필 절차

#### 1단계: 목차 확정

**사용자가 목차를 제공하는 경우:**
- 제공된 목차를 `project.yaml`의 `outline`에 그대로 기록
- wiki_queries에 각 챕터의 핵심 키워드 추출하여 추가

**목차가 없는 경우 (KB 기반 자동 제안):**
1. `wiki/concepts/_index.md` 스캔 → 주제와 관련된 기사 목록 파악
2. `wiki/sermons/_index.md` 스캔 → 저자가 자주 다룬 주제 파악
3. 관련 기사들의 `summary` 필드 검토 → 주제 클러스터 식별
4. 클러스터를 바탕으로 목차 초안 제안 → 사용자 확인 및 조정
5. 확정된 목차를 `project.yaml`에 저장

#### 2단계: 챕터별 순차 작성

목차 순서대로 하나씩 작성한다. 각 챕터마다:

**wiki/ 검색 (챕터 주제 기준):**
- `concepts/` — 챕터의 핵심 개념 기사 검색
- `sermons/` — 저자가 해당 주제를 다룬 설교 검색
- `books/` — 저자의 기존 저서 중 관련 부분 검색
- `references/` — 참고할 외부 자료 검색

**초안 작성 기준:**
- 도입부: 독자의 관심을 끄는 질문 또는 사례로 시작 (style.yaml의 argumentation 참조)
- 본론: KB에서 발견된 저자의 핵심 입장을 명확히 전개
- 결론: 독자에게 실천적 함의 또는 신학적 통찰 제시
- 문장 수준: style.yaml의 sentence_length 및 rhetoric 패턴 유지

**챕터 간 연결:**
- 이전 챕터 요약을 참조하여 흐름이 자연스럽게 이어지도록 작성
- 위키링크에서 발견된 관련 개념 간 연결을 본문에서 자연스럽게 언급

#### 3단계: 자기 검증

SKILL.md Step 5의 체크리스트 적용. 불일치 시 즉시 수정 후 저장.

### 유의사항

- 저자가 KB에서 다루지 않은 주제는 독단적으로 추가하지 않는다. 관련 내용이 KB에 없으면 사용자에게 알린다.
- 2차 자료(reference 타입)는 참고용으로만 활용하고, 저자 본인의 1차 자료를 우선한다.
- 목차가 많을 경우(10챕터 이상) 사용자와 우선 순위를 합의한 후 진행한다.

## 2. revision — 개정판

### 개요

기존 원고를 KB의 최신 상태와 비교하여 업데이트하고 보완한다. 원본의 논조와 구조를 최대한 유지하면서 새로운 통찰과 자료를 반영한다.

### 집필 절차

#### 1단계: 원본 로드 및 분석

1. `project.yaml`의 `base_document` 경로에서 원본 파일 로드
2. 원본의 목차와 섹션 구조 파악
3. `project.yaml`의 `outline`을 원본 구조에 맞게 갱신

#### 2단계: 섹션별 KB 비교

원본을 섹션 단위로 분할하여 순차 처리한다. 각 섹션마다:

**비교 분석:**
- 섹션의 핵심 주제를 파악하여 wiki/ 검색
- 원본 작성 시점 이후 추가된 관련 KB 기사 식별 (`updated` 날짜 기준)
- 원본 내용과 최신 KB 내용의 차이 분석

**변경 유형 분류:**

| 유형 | 설명 | 예시 |
|------|------|------|
| 추가 | KB에 새로운 내용이 있어 원본에 없는 내용 보완 필요 | 새 설교에서 발견된 심화 통찰 |
| 수정 | 저자의 입장이 발전하여 표현 업데이트 필요 | 신학적 강조점의 미세한 변화 |
| 삭제 | 원본 내용이 KB 최신 자료와 상충하거나 중복 | 이미 별도 챕터로 확장된 내용 |
| 유지 | 변경 불필요 | KB와 원본 내용이 일치하는 부분 |

#### 3단계: 사용자 승인 기반 수정

각 섹션의 변경 제안을 사용자에게 제시한다:

```
[섹션: {제목}]

변경 제안:
1. [추가] {내용 설명} — 근거: wiki/{기사명}
2. [수정] "{원본 표현}" → "{제안 표현}" — 이유: {설명}
3. [유지] {내용 설명}

승인하시겠습니까? (전체 승인 / 항목별 선택)
```

사용자 승인 후에만 수정을 적용한다. 미승인 항목은 원본 그대로 유지한다.

#### 4단계: 수정본 저장

승인된 수정사항을 반영한 섹션을 `drafts/`에 저장한다. 원본 파일은 변경하지 않는다.

### 유의사항

- 원본의 핵심 논지와 구조는 최대한 보존한다. 개정은 추가·보완이지 재작성이 아니다.
- 저자의 입장 변화가 감지될 경우(theology.yaml과 다른 뉘앙스 등) 사용자에게 명시적으로 알리고 판단을 맡긴다.
- `base_document` 경로가 없거나 파일이 존재하지 않으면 사용자에게 알리고 중단한다.

## 3. sermon_collection — 설교집

### 개요

`wiki/sermons/`에 축적된 설교 기사를 바탕으로 설교집을 편집한다. 시간순 또는 주제순으로 구성하고, 서문·소개글·연결 해설을 자동 생성한다.

### 집필 절차

#### 1단계: 수록 설교 선정

**전체 설교집인 경우:**
- `wiki/sermons/_index.md` 전체 스캔
- 모든 설교 기사 목록 확보

**특정 주제/기간 설교집인 경우:**
- 사용자가 지정한 주제 또는 기간 기준으로 필터링
- `wiki/concepts/_index.md`에서 관련 개념 기사 확인 → 해당 개념과 연결된 설교 탐색 (`_backlinks.json` 활용)

#### 2단계: 수록 순서 결정

**시간순(chronological):**
- 각 설교 기사의 `created` 또는 `date` 필드 기준 정렬
- 저자의 신학적 발전 흐름을 보여주는 데 적합

**주제순(topical):**
- 설교를 신학 주제별로 그룹핑 (`concepts/` 기사와 연결 기준)
- 각 그룹 내에서는 시간순 또는 논리적 흐름순으로 정렬
- 독자가 특정 주제를 집중적으로 공부하기에 적합

사용자에게 두 옵션을 제시하고 선택하게 한다.

#### 3단계: 서문 및 섹션 소개글 작성

**서문(preface):**
- 저자가 이 설교집을 통해 전달하고자 하는 핵심 메시지
- KB의 `concepts/` 기사에서 저자의 신학적 강조점 추출
- style.yaml의 어투와 rhetoric 패턴 적용
- 분량: 500-1000자 (저자의 문체에 따라 조정)

**섹션 소개글 (주제순인 경우):**
- 각 주제 그룹의 첫 페이지에 배치
- 해당 주제에 대한 저자의 입장 요약 (theology.yaml, concepts/ 기사 참조)
- 이 그룹의 설교들을 묶는 신학적 맥락 설명

#### 4단계: 설교 간 연결 해설 작성

각 설교 사이에 짧은 연결 해설(100-200자)을 삽입한다:
- 이전 설교와 다음 설교의 주제적 연결 설명
- 설교 시리즈가 있을 경우 시리즈 내 위치와 흐름 안내
- `_backlinks.json`의 관계 정보 활용

#### 5단계: 설교 본문 편집

각 설교 기사의 내용을 설교집 형식으로 정리:
- wiki/sermons/ 기사에서 설교 전문 또는 요약 확인
- 원본 설교문이 raw/entries/에 있는 경우 원본 참조
- 설교집에 적합한 형식으로 소제목, 단락 구성 정비

### 유의사항

- 설교 본문은 저자의 원본을 최대한 보존한다. 편집은 형식 정비에 그친다.
- wiki/sermons/에 기사가 없으면 먼저 `/publish-absorb`를 실행하도록 안내한다.
- 수록 설교 수가 많을 경우(30편 이상) 사용자와 범위를 먼저 합의한다.

## 4. commentary — 강해서

### 개요

성경 본문 단위로 구성하는 강해 주석서. `wiki/passages/`의 본문 기사를 기반으로 하며, 본문-해설-적용의 3단 구조를 따른다. 원어 참고자료는 `wiki/references/`에서 통합한다.

### 집필 절차

#### 1단계: 강해 범위 확정

사용자가 지정한 성경 본문 범위를 확인한다 (예: 로마서 1-8장, 요한복음 전체).

`wiki/passages/_index.md` 스캔하여 해당 범위의 본문 기사가 존재하는지 확인:
- 기사 존재: 해당 기사 목록을 `project.yaml`의 `outline`으로 설정
- 기사 부재: 어떤 본문이 KB에 없는지 사용자에게 알리고 (`/publish-absorb`로 추가 가능) 존재하는 본문만으로 진행할지 확인

#### 2단계: 본문별 강해 작성

각 본문 단위(단락 또는 장)마다 다음 3단 구조로 작성한다.

**본문 (Text):**
- 해당 성경 구절 인용
- vocabulary.md의 성경 번역본 기준 사용 (개역개정 / 새번역 등)
- vocabulary.md의 인용 형식 준수 (예: "" 로 감싸고 장절 표기)

**해설 (Exposition):**
- `wiki/passages/{본문명}/index.md` 로드 → 저자의 해석 확인
- `wiki/passages/{본문명}/chunks/` 로드 → 상세 주해 내용 확인
- 원어 참고자료 통합:
  - `wiki/references/_index.md` 스캔 → 관련 원어 자료 탐색
  - 헬라어/히브리어 단어 연구, 문법 분석 등 참조
  - 참고자료 출처 명시 (인용 형식: "~에 따르면", "~는 ~라고 설명한다")
- 관련 신학 개념 연결:
  - `wiki/concepts/_index.md` 스캔 → 해당 본문과 연결된 신학 주제
  - theology.yaml의 저자 입장과 일치하는 방향으로 해설

**적용 (Application):**
- 저자의 목회적 관심과 회중 상황 반영 (sermon_pattern.yaml의 application 패턴 참조)
- `wiki/sermons/` 검색 → 저자가 해당 본문을 설교한 전례가 있으면 참조
- 실천적 질문 또는 성찰 포인트 포함

#### 3단계: 본문 간 연결

강해서는 전체가 하나의 흐름을 가져야 한다:
- 각 단락 강해 끝에 다음 단락으로의 자연스러운 전환 문장 삽입
- 반복되는 신학 주제는 앞 강해를 상호 참조 (예: "앞서 3장에서 살펴본 칭의 개념은...")
- 저자의 전체 신학 체계 안에서 각 본문이 어디에 위치하는지 독자가 파악하도록 안내

### 원어 참고자료 통합 방법

`wiki/references/`에 원어 자료가 축적되어 있는 경우:

```
검색 흐름:
1. wiki/references/_index.md 스캔 — 원어 자료 목록 파악
2. 관련 자료 index.md summary 확인 — 해당 본문/단어 관련 여부 판단
3. 필요한 chunks/ 로드 — 실제 원어 분석 내용 확인
4. 저자 본인이 원어에 대해 언급한 내용 (1차 자료) 우선,
   참고 자료(2차 자료)는 보조적으로 활용
```

원어 자료가 없거나 부족한 경우: 원어 부분을 빈칸으로 두거나 사용자에게 관련 자료 추가를 제안한다.

### 유의사항

- 강해 해설은 저자의 신학적 입장(theology.yaml)과 일관되게 유지한다. 참고자료와 저자의 입장이 다를 경우, 저자의 입장을 우선하고 참고자료는 대화 상대로 다룬다.
- 본문 강해 분량이 지나치게 불균형하지 않도록 한다 (특정 절에 과집중 금지).
- wiki/passages/에 기사가 없는 본문은 해당 원본 자료가 수집·흡수되지 않은 것이므로 사용자에게 안내한다.

## 프로젝트 유형 선택 가이드

사용자가 유형을 명시하지 않았을 때 대화 맥락에서 추론한다:

| 사용자 발화 예시 | 추론 유형 |
|----------------|----------|
| "로마서 강해 써줘", "요한복음 주석" | commentary |
| "내 설교 모아서 책으로 만들어줘", "설교집 정리" | sermon_collection |
| "작년에 쓴 책 업데이트해줘", "개정판 작업" | revision |
| "은혜론 책 쓰고 싶어", "새 책 시작하자" | new_book |

확신이 없으면 사용자에게 직접 확인한다.
