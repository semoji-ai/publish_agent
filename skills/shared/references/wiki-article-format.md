# 위키 기사 포맷

모든 위키 기사는 동일한 구조를 따른다. LLM이 토큰 효율적으로 탐색할 수 있도록 설계되었으며, 옵시디언(Obsidian) 볼트와 완전히 호환된다.

---

## 1. 2-tier 디렉토리 구조

모든 기사는 단일 파일이 아니라 **디렉토리 + 파일** 구조를 사용한다.

```
wiki/{category}/{article_name}/
├── index.md          # 기사 본문 (YAML 프론트매터 + 요약 블록 + 본문)
└── chunks/           # 상세 섹션 청크 (본문이 길어질 때 분리)
    ├── 001.md        # 첫 번째 청크
    ├── 002.md        # 두 번째 청크
    └── ...
```

**실제 예시:**
```
wiki/concepts/구원론/
├── index.md
└── chunks/
    ├── 001.md        # 저자의 구원론 핵심 입장
    └── 002.md        # 칭의와 성화의 관계

wiki/sermons/2024_부활절_설교/
├── index.md
└── chunks/
    └── 001.md        # 설교 전문

wiki/people/칼빈/
├── index.md
└── chunks/
    ├── 001.md        # 신학적 영향
    └── 002.md        # 저자가 참조하는 칼빈 저작
```

**`{article_name}` 명명 규칙:**
- 한글 가능. 공백은 언더스코어(`_`)로 대체
- 날짜 포함 시 `{YYYY}_{제목}` 형식 (예: `2024_부활절_설교`)
- 옵시디언 위키링크에서 이 이름을 그대로 사용

## 2. index.md YAML 프론트매터 스키마

모든 `index.md`의 최상단에 위치하는 YAML 블록. 모든 필드 필수.

```yaml
---
title: 구원론
type: concept
created: 2026-04-21
updated: 2026-04-21
summary: "저자는 개혁주의 구원론에 기반하되 은혜의 무조건성을 강조하며, 칭의와 성화를 은혜의 연속적 사역으로 이해한다. 예정론적 토대 위에서 신자의 확신과 견인을 강조하는 것이 특징."
related:
  - "[[은혜]]"
  - "[[칭의]]"
  - "[[성화]]"
  - "[[예정론]]"
sources:
  - src_20260421_001
  - src_20260421_015
tags:
  - 조직신학
  - 구원
chunk_count: 2
---
```

### 필드별 상세 규격

| 필드 | 타입 | 설명 | 예시 |
|------|------|------|------|
| `title` | string | 기사 제목. `{article_name}`과 일치 권장 | `구원론` |
| `type` | enum | 기사 유형 (아래 목록 참조) | `concept` |
| `created` | date | 기사 최초 생성 날짜 (YYYY-MM-DD) | `2026-04-21` |
| `updated` | date | 기사 마지막 수정 날짜 (YYYY-MM-DD). 흡수/편집 시 갱신 | `2026-04-22` |
| `summary` | string | 2-4문장 핵심 요약. **LLM 검색의 Level 1 탐색 대상.** 기사 내용을 정확히 포착해야 함 | (위 예시 참조) |
| `related` | list | 관련 기사 위키링크 목록. `[[기사명]]` 형식 | `["[[은혜]]", "[[칭의]]"]` |
| `sources` | list | 이 기사 작성에 사용된 raw entry의 source_id 목록 | `["src_20260421_001"]` |
| `tags` | list | 분류 태그. 카테고리보다 세분화된 주제어 | `["조직신학", "구원"]` |
| `chunk_count` | integer | chunks/ 디렉토리 내 파일 수. 0이면 chunks/ 없음 | `2` |

**`type` 허용값:**
- `concept` — 신학 개념, 교리 (concepts/ 카테고리)
- `person` — 인물 (people/ 카테고리)
- `sermon` — 개별 설교 (sermons/ 카테고리)
- `book` — 저서/도서 (books/ 카테고리)
- `passage` — 성경 본문 단락 (passages/ 카테고리)
- `reference` — 참고자료 (references/ 카테고리)

**`summary` 작성 원칙:**
- 저자의 1차 자료 기반 기사: "저자는 ~라고 주장한다", "저자의 입장은 ~이다"로 시작
- 참고자료 기반 기사: "~에 따르면", "이 자료는 ~를 다룬다"로 시작
- 단순 주제 나열이 아니라, 기사의 핵심 주장/특징을 담아야 함
- 검색 질문에 답할 수 있어야 함 (예: "저자가 구원론에 대해 뭐라고 했지?" → summary로 답 가능)

## 3. 요약 블록 형식

`index.md` 본문 최상단(프론트매터 바로 아래, 제목 아래)에 위치하는 요약 블록. YAML `summary` 필드와 동일한 내용을 사람이 읽을 수 있는 형식으로 제시한다.

```markdown
---
{YAML 프론트매터}
---

# 구원론

> **요약:** 저자는 개혁주의 구원론에 기반하되 은혜의 무조건성을 강조하며, 칭의와 성화를 은혜의 연속적 사역으로 이해한다. 예정론적 토대 위에서 신자의 확신과 견인을 강조하는 것이 특징.

{본문 시작}
```

**요약 블록 규칙:**
- 반드시 `> **요약:**` 으로 시작하는 블록 인용 형식 사용
- YAML `summary` 필드의 내용과 동일해야 함 (중복이지만 필수 — 옵시디언에서 사람이 볼 때 가독성을 위해)
- 요약 블록 위에는 H1 제목만 허용

## 4. index.md 전체 구조 예시

```markdown
---
title: 구원론
type: concept
created: 2026-04-21
updated: 2026-04-21
summary: "저자는 개혁주의 구원론에 기반하되 은혜의 무조건성을 강조하며..."
related:
  - "[[은혜]]"
  - "[[칭의]]"
  - "[[성화]]"
sources:
  - src_20260421_001
  - src_20260421_015
tags:
  - 조직신학
  - 구원
chunk_count: 2
---

# 구원론

> **요약:** 저자는 개혁주의 구원론에 기반하되 은혜의 무조건성을 강조하며, 칭의와 성화를 은혜의 연속적 사역으로 이해한다.

## 저자의 핵심 입장

저자는 구원을 전적으로 하나님의 은혜로 이해하며, 이를 [[예정론]]의 토대 위에 세운다. 특히 [[칭의]]가 인간의 공로 없이 주어지는 하나님의 선언임을 강조한다.

## 칭의와 성화의 관계

저자는 [[칭의]]와 [[성화]]를 구분하되 분리하지 않는다. 자세한 논의는 chunks/001.md 참조.

## 관련 설교

- [[2024_부활절_설교]] — 은혜의 무조건성 강조
- [[2023_로마서_강해_3]] — 칭의와 성화의 관계

## 관련 저서

- [[믿음의_여정]] 3장 — 구원론 체계 정리

## Backlinks
```

**Backlinks 섹션:** 기사 하단에 `## Backlinks` 헤딩을 빈 채로 남긴다. 옵시디언이 자동으로 역링크를 여기에 표시하며, `_backlinks.json`에서 프로그래밍적으로도 접근 가능하다.

## 5. 위키링크 규칙

옵시디언의 `[[위키링크]]` 문법을 그대로 사용한다.

### 기본 형식

```markdown
[[기사명]]
```

`기사명`은 `wiki/{category}/{article_name}/`에서 `{article_name}`과 정확히 일치해야 한다.

### 표시 텍스트 변경 (앨리어스)

```markdown
[[구원론|구원에 관한 저자의 입장]]
```

`|` 뒤의 텍스트가 링크 레이블로 표시된다. 링크 대상은 `구원론` 기사.

### 섹션 링크

```markdown
[[구원론#칭의와 성화의 관계]]
```

특정 섹션으로 직접 링크. `#` 뒤에 섹션 헤딩 텍스트.

### 위키링크 사용 기준

**사용해야 하는 경우:**
- 다른 위키 기사가 이미 존재하거나 존재할 개념을 언급할 때
- YAML `related` 필드에 기재된 관련 기사 참조 시
- 주요 신학 개념, 인물, 설교, 저서를 처음 언급할 때

**사용하지 않는 경우:**
- 동일 기사 내에서 자기 참조
- 성경 구절 (예: `로마서 8:29`는 위키링크 불필요 — 단, 해당 구절 기사가 passages/에 있으면 링크 가능)
- 일반 단어나 접속사

**위키링크와 _backlinks.json 동기화:**
absorb 및 curate 실행 시, 모든 `index.md`에서 `[[링크]]` 패턴을 추출하여 `_backlinks.json`을 자동 재구축한다. 수동으로 `_backlinks.json`을 편집하지 말 것.

## 6. chunks/ 파일 구조

### 청크 파일 형식

```markdown
---
chunk_id: "구원론_001"
article: "구원론"
chunk_index: 1
title: "칭의와 성화의 관계"
---

# 칭의와 성화의 관계

{상세 내용 — 원문 기반, 섹션이 자체적으로 읽힐 수 있도록 완결된 형태}
```

### 청크 분리 기준

- `index.md` 본문이 **100줄 이상**이 되면 주제별로 chunks/ 분리를 검토
- 각 청크는 **독립적으로 읽힐 수 있는 완결된 섹션**이어야 함
- 청크 파일명: `001.md`, `002.md`, ... (순서 보장, 3자리 숫자)
- 청크 분리 후 `index.md`의 `chunk_count` 필드 업데이트 필수
- `index.md` 본문에 각 청크에 대한 간단한 참조 또는 요약 유지

## 7. 카테고리 _index.md 형식

각 카테고리 디렉토리(`wiki/concepts/`, `wiki/sermons/` 등)의 루트에 위치하는 인덱스 파일.

### 형식

```markdown
# Concepts Index

- [[구원론]] — 개혁주의 구원론, 은혜의 무조건성 강조
- [[은혜]] — 칭의적 은혜와 성화적 은혜를 구분하는 저자의 입장
- [[언약]] — 은혜 언약 중심, 행위 언약과의 관계
- [[칭의]] — 법정적 칭의 이해, 믿음으로만의 강조
- [[성화]] — 점진적 성화, 성령의 역할 중심
```

### 작성 규칙

- 각 줄: `- [[기사명]] — {한줄 요약}` 형식
- `{한줄 요약}`: 해당 기사 YAML의 `summary` 첫 문장을 압축한 내용 (30자 내외)
- 정렬: 알파벳/가나다순 또는 주제 연관성 순 (일관성 있게 유지)
- **LLM 검색의 Level 0 탐색 대상**: 이 파일이 기사 발견의 첫 진입점
- absorb 완료 시 자동 재생성됨

### 마스터 _index.md (wiki/_index.md)

루트 `wiki/_index.md`는 전체 기사를 카테고리별로 구분하여 나열한다.

```markdown
# Wiki Index

> 총 {N}개 기사 | 마지막 업데이트: {date}

## Concepts ({n}개)
- [[구원론]] — 개혁주의 구원론, 은혜의 무조건성 강조
- [[은혜]] — 칭의적 은혜와 성화적 은혜 구분

## People ({n}개)
- [[칼빈]] — 저자가 주요 신학적 자원으로 참조하는 개혁주의 신학자

## Sermons ({n}개)
- [[2024_부활절_설교]] — 은혜의 무조건성, 로마서 5장 기반

## Books ({n}개)
...

## Passages ({n}개)
...

## References ({n}개)
...
```

**KB가 커지면** 루트 `_index.md` 대신 **카테고리별 `_index.md`를 먼저 스캔**하여 토큰 효율을 유지한다 (검색 전략 → `search-strategy.md` 참조).

## 8. Anti-cramming 규칙 (과밀 방지)

**목적:** 하나의 기사에 무관한 내용까지 억지로 합치는 것을 방지한다.

### 분리 트리거 조건

다음 두 조건을 **모두** 충족할 때 새 항목을 기존 기사에 병합하지 말고 **별도 기사로 분리**한다:

1. **기존 기사 분량**: `index.md` 본문 + chunks/ 전체가 **200줄 이상**
2. **독립 가능성**: 새 내용이 기존 기사의 하위 주제로서 **독립적인 기사가 될 수 있는 수준**의 내용 (최소 15줄 이상, 독자적인 논점/사례 포함)

### 분리 절차

1. 기존 기사에서 새 기사로 이동할 내용의 범위 결정
2. 새 기사 디렉토리 생성 + `index.md` 작성
3. 기존 기사에 새 기사로의 위키링크 추가
4. 기존 기사의 `related` 필드에 새 기사 추가
5. `_backlinks.json` 업데이트

### 분리 판단 예시

- **분리 O**: `구원론` 기사(250줄)에 `칭의` 관련 내용 30줄 추가 → `칭의` 별도 기사로 분리
- **분리 X**: `구원론` 기사(150줄)에 `칭의` 관련 내용 10줄 추가 → 기존 기사에 병합 (분량 미달 또는 독립 불가)

## 9. Anti-thinning 규칙 (과소 방지)

**목적:** 내용이 너무 적은 스텁(stub) 기사가 양산되는 것을 방지한다.

### 병합 트리거 조건

새 기사를 생성하려 할 때, 해당 내용이 **15줄 미만**이면 별도 기사로 생성하지 말고 관련 기사에 병합한다.

### 병합 대상 선택 기준

1. `_index.md`에서 가장 연관성 높은 기존 기사 탐색
2. 없으면 가장 가까운 상위 개념 기사에 섹션으로 추가
3. 상위 개념 기사도 없으면 임시로 `개요` 섹션을 가진 새 기사 생성 허용 (단, 추후 보완 필요 표시)

### 적용 예외

다음 경우에는 15줄 미만이어도 별도 기사로 생성 가능:
- **고유명사 기사** (인물, 특정 설교 제목, 특정 저서): 추후 내용 보완을 위해 스텁 허용
- **교차 참조 허브**: 여러 기사에서 링크되는 개념으로 별도 기사가 명확히 필요한 경우

### 15줄 계산 기준

- YAML 프론트매터 제외
- 빈 줄 포함
- 요약 블록(blockquote) 포함
- 섹션 헤딩 포함
