# 위키 검색 전략

Publish Agent는 별도 임베딩 API 없이 **LLM 자체를 검색 엔진**으로 활용한다. 토큰 효율을 위해 3단계 계층적 요약 검색을 사용한다.

**핵심 원칙:** 필요한 것만 로드한다. Level 0부터 시작하여 충분한 정보를 찾으면 더 깊이 들어가지 않는다.

---

## 1. 3-레벨 계층적 검색

```
Level 0: 카테고리 _index.md (또는 루트 _index.md)
          ↓ 관련 기사 후보 선정
Level 1: 후보 기사의 index.md summary 필드 (또는 요약 블록)
          ↓ 관련성 확인 + 추가 탐색 결정
Level 2: 확정된 기사의 chunks/ 상세 내용
          ↓ 구체적 근거/세부 내용 확인
```

### Level 0 — 카테고리 인덱스 스캔

**읽는 파일:** `wiki/{category}/_index.md` 또는 `wiki/_index.md`

**내용:** 기사 제목 + 한줄 요약 목록

**목적:** 어떤 기사가 관련 있는지 후보를 선별한다.

**예시 (wiki/concepts/_index.md):**
```
- [[구원론]] — 개혁주의 구원론, 은혜의 무조건성 강조
- [[은혜]] — 칭의적 은혜와 성화적 은혜를 구분하는 저자의 입장
- [[칭의]] — 법정적 칭의 이해, 믿음으로만의 강조
```

**토큰 비용:** 매우 낮음 (기사당 1-2줄)
**기대 출력:** "후보 기사: `구원론`, `칭의`"

### Level 1 — 기사 요약 확인

**읽는 파일:** `wiki/{category}/{article_name}/index.md`

**참조 위치:** YAML 프론트매터의 `summary` 필드 + 요약 블록 (`> **요약:** ...`)

**목적:** 후보 기사가 실제로 관련이 있는지 확인하고, 충분한 답을 찾거나 Level 2로 진입할지 결정한다.

**예시 (summary 읽기):**
```yaml
summary: "저자는 개혁주의 구원론에 기반하되 은혜의 무조건성을 강조하며, 칭의와 성화를
         은혜의 연속적 사역으로 이해한다. 예정론적 토대 위에서 신자의 확신과 견인을 강조."
```

**토큰 비용:** 낮음 (기사당 3-6줄 — summary + 상단 섹션 구조 확인)
**기대 출력:** "이 기사가 관련 있음 / 없음. Level 2 진입 필요/불필요."

### Level 2 — 청크 상세 내용 로드

**읽는 파일:** `wiki/{category}/{article_name}/chunks/{번호}.md`

**목적:** 구체적인 근거, 인용, 세부 논점이 필요할 때 사용.

**토큰 비용:** 청크 내용에 따라 가변 (청크당 50-200줄)
**언제 사용:** 인용 문구, 구체적 논증, 특정 설교/본문의 상세 내용이 필요한 경우

**청크 선택 방법:**
1. `index.md`의 섹션 구조 확인 (어떤 섹션이 어떤 청크에 있는지)
2. 필요한 청크만 선택적으로 로드
3. 모든 청크를 로드하지 않음

## 2. 토큰 예산 관리

### 권장 토큰 예산 (기준: 200K 컨텍스트 창)

| 단계 | 토큰 예산 | 설명 |
|------|----------|------|
| Level 0 스캔 | 1,000-3,000 | 카테고리 _index.md 1-3개 |
| Level 1 확인 | 500-2,000 per article | 기사 summary + 구조 파악 |
| Level 2 로드 | 1,000-5,000 per chunk | 청크 상세 내용 |
| 저자 프로필 | 2,000-4,000 | 4개 프로필 파일 전체 |
| 작업 컨텍스트 | 나머지 | 현재 초안, 사용자 요청 등 |

### 토큰 절약 전칙

1. **루트 인덱스보다 카테고리 인덱스 우선:** KB가 50개 이상 기사를 가지면, `wiki/_index.md` 전체를 읽지 말고 관련 카테고리 `_index.md`만 읽는다.

2. **summary만으로 충분하면 chunks/ 로드 금지:** 질문에 대한 답이 summary에 있으면 Level 2 진입하지 않는다.

3. **관련 없는 후보 즉시 기각:** Level 0에서 후보를 선정할 때, 명확히 무관한 기사는 즉시 제외한다.

4. **프로필은 한 번만 로드:** 세션 내에서 저자 프로필(4개 파일)은 처음 한 번만 로드하고 재사용한다.

5. **청크는 필요한 것만:** `chunk_count: 3`이어도 첫 번째 청크가 충분하면 나머지 로드 불필요.

## 2.5 컨텍스트 예산 (검색 중 토큰 한도)

검색 중 컨텍스트를 과도하게 소진하면 실제 작업(집필, 심사 등)에 사용할 토큰이 부족해진다. 각 레벨의 토큰 상한을 엄수한다.

### 레벨별 상한

| 레벨 | 상한 | 초과 시 조치 |
|------|------|------------|
| Level 0 스캔 | 5K 토큰 이하 | 스캔 대상 카테고리 수 줄이기 |
| Level 1 요약 누적 | 10K 토큰 이하 | 가장 관련성 높은 기사 3-5개만 선택 후 나머지 기각 |
| Level 2 청크 로드 | 20K 토큰 이하 | 청크 수 제한, 필요한 섹션만 선택적 로드 |
| 검색 전체 합산 | 35K 토큰 이하 | 이 한도를 초과하면 검색 즉시 중단, 확보된 내용으로 진행 |

### 상한 초과 방지 규칙

1. **Level 0에서 후보 3개 이하로 압축** — _index.md 스캔 후 관련 없는 기사는 즉시 기각. 후보 5개를 넘기지 않는다.

2. **Level 1 요약은 summary 필드만** — index.md 전체를 읽지 않는다. 프론트매터의 `summary` 필드와 서두 요약 블록만 참조.

3. **Level 2는 필요한 청크 1-2개만** — `chunk_count`가 5여도 필요한 섹션이 있는 청크 1-2개만 로드. 모든 청크 로드 금지.

4. **루트 _index.md는 최후 폴백만** — KB 기사 수가 50개 이상이면 `wiki/_index.md` 전체 스캔은 Level 0으로 사용하지 않는다. 반드시 카테고리 인덱스를 먼저 시도한다.

5. **검색 결과를 즉시 활용** — 검색이 끝난 기사의 원문은 컨텍스트에서 제거. 핵심 인용과 참조 정보만 유지.

→ 스킬별 토큰 예산 전체: `shared/references/context-management.md`의 "스킬별 토큰 예산" 섹션 참조

## 3. 질문 유형별 검색 시작점

질문의 성격에 따라 어떤 카테고리 인덱스를 먼저 탐색할지 결정한다.

### 신학 개념 질문

**예:** "저자의 칭의론은?", "은혜에 대해 뭐라고 했지?", "성화를 어떻게 이해해?"

```
시작: wiki/concepts/_index.md
  → 관련 개념 기사 후보 선정
  → 각 후보의 index.md summary 확인
  → 필요 시 chunks/ 로드

보조: wiki/sermons/_index.md (설교에서 해당 개념을 다룬 경우)
     wiki/books/_index.md (저서에서 해당 개념을 다룬 장)
```

### 성경 본문 질문

**예:** "로마서 8장에 대해 뭐라고 했지?", "요한복음 3:16 설교 있어?", "시편 23편 자료"

```
시작: wiki/passages/_index.md
  → 해당 본문 기사 탐색
  → 없으면: wiki/sermons/_index.md (해당 본문 기반 설교)

보조: wiki/concepts/_index.md (본문의 핵심 교리가 개념 기사로 있는 경우)
```

### 설교 관련 질문

**예:** "부활절 설교 어떻게 했지?", "지난 번 로마서 강해", "설교 패턴 분석"

```
시작: wiki/sermons/_index.md
  → 날짜, 제목, 본문 기준 필터링
  → 해당 설교 index.md summary 확인
  → 상세 내용 필요 시 chunks/ 로드

보조: wiki/passages/_index.md (동일 본문의 다른 설교)
     wiki/concepts/_index.md (설교의 주제 개념)
```

### 인물 관련 질문

**예:** "칼빈에 대해 자료 있어?", "저자가 루터를 어떻게 인용하나?", "바울에 대한 기사"

```
시작: wiki/people/_index.md
  → 해당 인물 기사 탐색

보조: wiki/concepts/_index.md (해당 인물의 신학적 영향이 개념으로 정리된 경우)
     wiki/references/_index.md (해당 인물의 저서를 참조한 경우)
```

### 저서 관련 질문

**예:** "믿음의 여정 어디서 이 내용 다뤘지?", "어떤 책에서 칭의를 설명했나?"

```
시작: wiki/books/_index.md
  → 해당 저서 기사 탐색

보조: wiki/concepts/_index.md (저서에서 다루는 핵심 개념)
```

### 참고자료 질문

**예:** "웨스트민스터 신앙고백에 관한 자료?", "신학 논문 있어?"

```
시작: wiki/references/_index.md
  → 해당 자료 탐색

보조: wiki/concepts/_index.md (참고자료가 다루는 개념)
```

### "내가 ~에 대해 뭐라고 했지?" 유형 (저자 자신의 과거 발언 탐색)

**예:** "내가 칭의에 대해 뭐라고 했지?", "은혜에 관해 내 입장은?"

```
1순위: authors/{author_id}/theology.yaml (신학적 입장 직접 확인)
2순위: wiki/concepts/_index.md → 해당 개념 기사의 summary
3순위: wiki/sermons/_index.md → 관련 설교 탐색
```

## 4. 폴백 전략 (찾지 못한 경우)

### Fallback Level 1: 카테고리 확장

초기 카테고리에서 찾지 못하면 관련 카테고리로 확장.

```
예: concepts/_index.md에서 못 찾은 경우
  → sermons/_index.md 탐색 (설교에서 해당 개념을 다룬 경우)
  → books/_index.md 탐색 (저서에서 해당 개념을 다룬 경우)
```

### Fallback Level 2: 루트 인덱스 스캔

카테고리 인덱스들에서 모두 찾지 못한 경우, `wiki/_index.md` 전체 스캔.

**주의:** 루트 인덱스는 KB 전체 기사를 나열하므로 토큰 비용이 높다. 반드시 카테고리 스캔을 먼저 시도한 후 폴백으로만 사용.

### Fallback Level 3: "없음" 결론

루트 인덱스 스캔 후에도 관련 기사가 없으면:
1. "위키에 이 주제에 관한 기사가 아직 없습니다"로 명확히 보고
2. raw/entries/에서 아직 흡수되지 않은 관련 자료가 있는지 확인 제안
3. 새 자료 수집 제안 (`/publish-collect` 안내)

**없는 내용을 만들어 제공하지 않는다.** KB에 없는 내용을 저자의 입장인 것처럼 생성하는 것은 금지.

## 5. 다중 기사 탐색 패턴

복잡한 질문(여러 개념 연관)에서는 다중 기사를 탐색한다.

### 예시: "칭의와 성화의 관계에 대한 저자의 입장"

```
Step 1 (Level 0): concepts/_index.md 스캔
  → 후보: [[칭의]], [[성화]], [[구원론]]

Step 2 (Level 1): 3개 기사 summary 확인
  → [[칭의]] summary: "법정적 칭의 이해..."
  → [[성화]] summary: "점진적 성화, 성령의 역할..."
  → [[구원론]] summary: "칭의와 성화를 연속적 사역으로..."

Step 3: [[구원론]] 기사가 두 개념의 관계를 다루고 있음 확인
  → [[구원론]]의 chunks/001.md (칭의와 성화 관계 섹션) 로드

Step 4: 충분한 정보 확보 → 답변 구성
```

### 탐색 중단 기준

다음 중 하나 도달 시 탐색 중단:
1. 질문에 답하기 충분한 정보 확보
2. 토큰 예산의 50% 소진 (나머지는 답변 생성에 사용)
3. 5개 이상의 기사 Level 1 탐색 완료

## 6. 검색 품질의 기반: summary 품질

**검색 품질은 absorb 시 summary 작성 품질에 전적으로 의존한다.**

좋은 summary 조건:
- 기사의 핵심 주장/특징을 2-4문장으로 압축
- 예상 검색 질문에 직접 답할 수 있어야 함
- "이 기사는 ~에 대해 다룬다"가 아니라 "저자의 ~에 대한 입장은 ~이다"

나쁜 summary 예시 (피해야 함):
```
"이 기사는 구원론에 관한 내용입니다."  ← 검색에 도움 안 됨
```

좋은 summary 예시:
```
"저자는 개혁주의 구원론에 기반하되 은혜의 무조건성을 강조하며, 칭의와 성화를
 은혜의 연속적 사역으로 이해한다. 예정론적 토대 위에서 신자의 확신과 견인을 강조."
```

## 7. 검색 결과 활용 규칙

### 인용 표기

검색으로 찾은 내용을 인용할 때:
- 출처: `wiki/{category}/{article_name}/index.md` 또는 `chunks/{번호}.md`
- 원본 raw entry의 `source_id` 추적 가능 (기사의 `sources` 필드 참조)

### 저자 입장 vs 참고자료 구분

- **저자 입장**: `sources`에 `type: primary` raw entry가 포함된 기사 내용
- **참고자료**: `type: reference` raw entry 기반 기사 내용

결과 제시 시 이 구분을 명확히 한다:
- "저자는 ~라고 주장합니다" (primary 기반)
- "~에 따르면 / ~가 인용한 자료에 따르면" (reference 기반)

### 신뢰도 표시

raw entry의 `confidence: low`인 소스가 포함된 기사는 검색 결과 제시 시 주의 표시:
- "이 내용은 추출 신뢰도가 낮은 자료에 기반합니다. 원본 확인을 권장합니다."
